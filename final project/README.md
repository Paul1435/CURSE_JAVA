# Сервер системы учёта финансовых операций

## Описание проекта

Данное приложение представляет собой серверную часть системы учёта финансовых операций организации. Сервер обеспечивает взаимодействие между клиентскими приложениями сотрудников и базой данных.

После подключения клиента сервер выполняет регистрацию или авторизацию пользователя, определяет его роль и начинает обработку поступающих запросов.

Основная задача системы — предоставить сотрудникам возможность:

- зарегистрироваться и авторизоваться в системе;
- создавать заявки на получение денежных средств;
- просматривать собственные доходы;
- просматривать произведённые расходы;
- получать историю финансовых операций.

Вся информация хранится в базе данных и остается доступной после повторного входа пользователя.

---

# Основные возможности

## Регистрация и авторизация пользователей

Сервер поддерживает:

- регистрацию новых сотрудников;
- авторизацию пользователей;
- проверку логина и пароля;
- получение роли пользователя;
- получение идентификатора сотрудника.

После успешной авторизации для каждого клиента создаётся отдельный поток обработки запросов.

---

## Работа с денежными заявками

Пользователь может:

- создать новую заявку;
- указать необходимую сумму;
- добавить описание заявки;
- отправить заявку на сервер;
- просматривать список собственных заявок.

Все заявки сохраняются в базе данных.

---

## Учёт доходов

Система позволяет:

- добавлять информацию о доходах;
- хранить сумму дохода;
- хранить дату получения;
- хранить описание операции;
- получать список собственных доходов.

---

## Учёт расходов

Система хранит информацию:

- о расходах сотрудников;
- сумме расхода;
- ответственном сотруднике;
- описании операции;
- дате выполнения.

---

## Просмотр финансовой информации

Пользователь может получить:

- список доходов;
- список расходов;
- список денежных заявок.

# Структура базы данных

При первом запуске сервер автоматически создаёт необходимые таблицы.

## work_info_employees

Хранит информацию о сотрудниках.

| Поле | Назначение |
|------|------------|
| employee_id | идентификатор сотрудника |
| last_name | фамилия |
| first_name | имя |
| middle_name | отчество |
| post | должность |
| username | логин |
| password_hash | пароль пользователя |

---

## incomes

Хранит информацию о доходах сотрудников.

| Поле | Назначение |
|------|------------|
| income_id | идентификатор записи |
| employee_id | сотрудник |
| amount | сумма |
| description | описание |
| date | дата получения |

---

## expenses

Хранит информацию о расходах.

| Поле | Назначение |
|------|------------|
| expenses_id | идентификатор записи |
| employee_id | сотрудник |
| amount | сумма |
| description | описание |
| date | дата операции |
| responding_user_id | ответственный сотрудник |

---

## money_requests

Хранит заявки сотрудников на получение денежных средств.

| Поле | Назначение |
|------|------------|
| request_id | идентификатор заявки |
| employee_id | сотрудник |
| amount | сумма |
| description | описание |
| status | статус заявки |
| date_requested | дата создания |
| date_responded | дата обработки |

# Принцип работы сервера

1. Запускается серверное приложение.
2. Выполняется подключение к базе данных.
3. Проверяется существование необходимых таблиц.
4. При отсутствии таблиц они создаются автоматически.
5. Открывается серверный сокет.
6. Сервер начинает ожидать подключения клиентов.
7. После подключения клиента выполняется регистрация или авторизация.
8. Для каждого клиента создаётся отдельный поток обработки.
9. Поток принимает запросы клиента.
10. В зависимости от типа запроса вызывается соответствующий DAO-класс.
11. Полученный результат сериализуется и отправляется клиенту.

# Используемые шаблоны проектирования

## DAO (Data Access Object)

Все обращения к базе данных инкапсулированы в отдельных DAO-классах.

Преимущества:

- отделение бизнес-логики от SQL;
- упрощение сопровождения проекта;
- повышение расширяемости системы.

---

## Singleton

Используется для:

- DatabaseHelper;
- DAO-классов.

Паттерн гарантирует существование единственного экземпляра объекта.

---

## Многопоточность

Каждый подключившийся клиент обслуживается отдельным потоком.

Это позволяет серверу одновременно работать с несколькими пользователями.

---

# Протокол взаимодействия

Клиент и сервер взаимодействуют посредством TCP-соединения.

Передача данных осуществляется с использованием сериализации Java-объектов через `ObjectInputStream` и `ObjectOutputStream`.

Каждый запрос содержит тип выполняемой операции и необходимые данные. Сервер обрабатывает запрос, выполняет соответствующие действия с базой данных и отправляет клиенту результат выполнения.

---

# Безопасность

При авторизации выполняется:

- проверка существования пользователя;
- проверка корректности логина;
- проверка пароля;
- запрет доступа при неверных учетных данных.

> **Примечание:** в текущей версии проекта пароли хранятся в базе данных. Для промышленного использования рекомендуется хранить их в виде криптографических хешей (например, BCrypt).

# Запуск проекта

## Требования

- Java 17 или выше;
- Maven;
- SQL Database;
- настроенное подключение к базе данных.

## Запуск

1. Клонировать репозиторий.

```bash
git clone <repository_url>
```

2. Настроить подключение к базе данных.

3. Собрать проект.

```bash
mvn clean package
```

4. Запустить серверное приложение.
